# Student Guide Layout Template Contract

This contract defines the approved BuildStak student study-guide layout. Prof Greg must not invent a new layout for each course.

## Approved Template

The approved visual reference is the Blueprint Reading student guide cover/layout approved by the user:

- full-page BuildStak cover with navy outer field;
- orange border;
- white inner page area;
- subtle blueprint grid accent on the left;
- BuildStak symbol near the upper-right of the white page;
- `STUDY GUIDE` label in orange;
- course title as the dominant title;
- orange divider line;
- lesson title below the divider;
- lesson number;
- level;
- quiet quote line near the bottom;
- `BuildStak Learning Series` footer text.

## Required Page Sequence

Every student-facing study guide must follow this sequence unless the user explicitly approves a different template:

1. Cover page using the approved BuildStak study-guide cover system.
2. Introduction and Learning Objectives on the next page.
3. Lesson body starts on a new page after the Learning Objectives page.
4. Summary and Key Takeaways on its own page.
5. Glossary on its own page.
6. References on its own page.

Do not insert a Lesson Roadmap. The student guide begins with Introduction immediately after the cover.

## Body Layout

- Lesson body must not start on the same page as the front-matter introduction or learning objectives.
- Section headings must use `Section NN - Section Name`.
- Never use abbreviated labels such as `SEC.`.
- Never leave a section heading or one-line section opening isolated before a page break.
- Never split a callout box across pages.
- Do not place two callout boxes back-to-back without explanatory body text between them. If two adjacent callouts serve the same teaching moment, combine them into one box.

## Figures

- Captions must be concise and student-facing.
- Do not print "learning line" or internal teaching-purpose language in captions.
- Keep teaching purpose in QA/source artifacts only.

## References

- References must not expose local file paths, internal source folders, source rankings, reliability notes, or production rationale.
